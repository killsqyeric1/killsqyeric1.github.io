1.总结 kubernetes 控制平面的各组件功能：

kube-apiserver

  • 是 Kubernetes 控制平面的前端接口，提供 RESTful API 供用户、集群组件和外部系统与集群交互。
  • 负责验证和配置 API 对象（如 Pods、Services、Deployments 等）。
  • 所有其他组件都通过 kube-apiserver 读写集群状态，是唯一能直接访问 etcd 的组件。

etcd

  • 是一个高可用、强一致性的分布式键值存储系统，用于保存 Kubernetes 集群的所有关键数据（如节点信息、Pod 状态、配置等）。
  • 是 Kubernetes 的唯一真实数据源。

kube-scheduler

  • 负责将新创建的 Pod 调度到合适的节点上运行。
  • 根据资源需求、策略约束（如亲和性/反亲和性）、数据局部性、工作负载干扰等因素进行调度决策。
  • 调度过程分为“过滤”（筛选可行节点）和“打分”（选择最优节点）两个阶段。

kube-controller-manager

  • 是一组控制器的集合，负责维护集群的期望状态。
  • 这些控制器通过 kube-apiserver 监听集群状态变化，并采取相应操作使实际状态趋近于期望状态。

Node Controller：监控节点健康状态，在节点不可达时做出响应。
Replication Controller / ReplicaSet Controller：确保指定数量的 Pod 副本始终运行。
Deployment Controller：管理 Deployment 对象，支持滚动更新和回滚。
Endpoint Controller：维护 Service 与 Pod 之间的映射关系。
Service Account & Token Controllers：为命名空间自动创建默认服务账户和 API 访问令牌等。

3.pod的创建流程：

3.1: 执行 kubectl create -f nginx-deploy.yaml → kubectl 向 kube-apiserver 发起创建请求；
3.2:kube-apiserver 完成「认证 / 授权」后，将 Deployment 的「期望状态」（比如 3 个副本）写入 etcd，并返回创建成功；
3.3:kube-controller-manager 中的 Deployment 控制器，通过 apiserver 发现新的 Deployment，自动创建对应的 ReplicaSet；
3.4:eplicaSet 控制器发现「期望 3 个 Pod，实际 0 个」，通过 apiserver 创建 3 个 Pod 的资源对象，写入 etcd；
3.5:kube-scheduler 监听 apiserver，发现 3 个「待调度的 Pod」，为每个 Pod 筛选并打分，选出最合适的 Node 节点，将调度结果（Pod 绑定到哪个 Node）更新到 etcd；
3.6:对应 Node 节点上的 kubelet，通过 apiserver 发现「自己被分配了 Pod」，调用容器运行时（Docker/containerd）创建 Pod，Pod 启动成功后，kubelet 将 Pod 的「实际运行状态」上报给 apiserver，apiserver 更新到 etcd；
3.7: kube-proxy 监控到 Pod 创建后，更新本地的 iptables/ipvs 规则，让 Service 可以转发流量到新 Pod；
3.8:后续如果某个 Pod 宕机 → ReplicaSet 控制器发现「实际 2 个 Pod≠期望 3 个」→ 自动创建新 Pod → scheduler 重新调度 → kubelet 创建 Pod，完成自愈。
